# ① LP文言修正＋機能説明拡充

## Context

`plans/pc-moonlit-hartmanis.md` に記録済みのロードマップの①にあたる作業。`#77 サーブ・レシーブ起点の3球目/4球目パターン分析`（Sprint 1〜3）が実装・マージ済みになったにもかかわらず、LP（`app/views/homes/top.html.erb`）の「T.T.LOGでできること」セクションには④番目の項目に「（開発中）」という古い表記が残っている。実装済みの機能をユーザーに正しく伝えるため、文言を実態に合わせて更新する。

調査の結果、④だけでなく①の「20種の打法別得点率を分析」も数字が実態とズレていることが判明した（`Score.batting_style` enumは20種類だが、実際の打法別分析画面では `receive` を除いた19種類のみが集計・表示される。`match_infos_controller.rb:317` `@batting_scores = @match_info.scores.where.not(batting_style: :receive)`）。あわせて修正する。

④へのリンク追加については、①②③が非リンクのテキストカードであることとのトーン統一を優先し、今回は見送る（ユーザー確認済み）。導線強化（NEWバッジ・ヘッダーナビ追加等）は別タスク②で対応する。

## 対象ファイル

- `app/views/homes/top.html.erb`（44〜47行目、機能紹介リスト）

## 実装内容

`app/views/homes/top.html.erb` 44〜47行目を以下のように修正する。

- ①: 「20種の打法別得点率を分析」→「19種の打法別得点率を分析」に数字を修正（文言の他の部分はそのまま）
- ②③: 現状の実装（`chatgpt_service.rb`によるAIアドバイス、`_score_progression.html.erb`によるゲームごとの得点推移）と文言が一致していることを調査で確認済み。修正不要
- ④: 「（開発中）」を削除し、3球目/4球目パターン分析まで実装済みであることが伝わる文言に更新する。リンクは追加しない（①②③との見た目トーンを揃えるため）
  - 修正例: `<li><span class="icon">④</span>サーブ・レシーブ起点の3球目/4球目パターンまで分析 — 序盤の展開力が一目でわかる</li>`
  - 「（開発中）」の削除以外に、他の項目と同様の文体（体言止め＋ダッシュで効果を添える）に揃える

## 進め方

1. 新規ブランチを作成する（例: `fix/top-page-serve-receive-copy`）
2. `app/views/homes/top.html.erb` の44〜47行目を上記方針で編集
3. `bundle exec rspec && bundle exec rubocop --parallel` を実行し、パスすることを確認（ビュー修正のみだがCLAUDE.mdのルールに従い実行）
4. 1コミットにまとめる（plansファイルの更新があれば実装コミットと同時にコミット）
5. PR作成はユーザーの明示的な指示があってから行う

planner/generator/evaluatorのサブエージェントは呼ばない（軽量プランのみで直接実装するタスクのため）。

## 検証方法

- `bin/dev` でローカルサーバーを起動し、トップページ（`/`）を開いて「T.T.LOGでできること」セクションの①④の文言が意図通り表示されることを目視確認
- ①の数字が「19種」になっていること、④に「（開発中）」の文字が残っていないことを確認
- `bundle exec rspec` と `bundle exec rubocop --parallel` が両方パスすること

# ④ Phase 3を見据えた「データ蓄積の予告」表現 実装プラン

## Context（なぜこの実装をするのか）

`plans/pc-moonlit-hartmanis.md` のロードマップで①〜③（LP文言修正、アプリ内導線強化、Phase 0の成長ダッシュボード実装）が完了した。
③で実装された「成長ダッシュボード」（技術別・得点内訳における使用率の月別/週別推移グラフ）は、試合データを継続的に記録するほど価値が増す「積み上げ型」の機能。この積み上げ価値は、将来の Phase 3（課金導入）で訴求材料にする予定であり、そのための布石として、今の段階から「データが溜まるとこう見える／こう良くなる」という将来価値を予告するコピーを追加する。

現状確認した事実:

- 成長ダッシュボードへの導線はヘッダーナビ（`app/views/shared/_header.html.erb:28-32, 53-57`）にNEWバッジ付きで既に存在する。
- LP（`app/views/homes/top.html.erb`）の「T.T.LOGでできること」セクション（44-50行目）には①〜④の4項目があるが、成長ダッシュボードに関する項目がまだ無い。
- ダッシュボード自体（`app/views/growth_dashboards/index.html.erb`）はデータが0件のとき、35-38行目で「まだ表示できる試合データがありません」という素っ気ない空状態メッセージのみを表示している。

ユーザーとの確認により、今回のスコープは以下の通り:

- 実装範囲: **LPへの項目追加** ＋ **ダッシュボード空状態メッセージの改善**（データが少ない場合の中間メッセージは対象外）
- 表現形式: **テキストコピーのみ**（画像・新規コンポーネントは作らない）

規模は極小（コピー修正のみ、ロジック変更なし）なので、ロードマップどおり planner/generator/evaluator は使わず、通常のプラン→直接実装→1PRで対応する。

## 実装内容



### 1. LPに成長ダッシュボードの項目を追加

**対象ファイル**: `app/views/homes/top.html.erb`（44-50行目「T.T.LOGでできること」）

現状の①〜④の後ろに⑤を追加する:

```erb
<li><span class="icon">⑤</span>技術別の使用率を月別・週別に可視化 — 試合を重ねるほど、あなたの成長データが積み上がっていく</li>
```

- 既存の①〜④のトーン（「〜できる」「〜がわかる」で終わる短文）に揃える。
- 「積み上げ」「重ねるほど」など、継続利用すると価値が増すことが伝わる語を入れる（Phase 3の布石としての狙いを反映）。
- 番号付きリストなので `⑤` の絵文字/記号が他と視覚的に揃うか確認する（①②③④はUnicode丸数字）。



### 2. ダッシュボード空状態メッセージの改善

**対象ファイル**: `app/views/growth_dashboards/index.html.erb`（35-38行目）

現状:

```erb
<% if @series.empty? %>
  <p class="text-muted">
    まだ表示できる試合データがありません。試合を登録すると、<%= Score.human_enum_name(:batting_style, @batting_style) %>の得点内訳における使用率の推移がここに表示されます。
  </p>
<% else %>
```

改善後（既存文に将来価値の一文を追加する）:

```erb
<% if @series.empty? %>
  <p class="text-muted">
    まだ表示できる試合データがありません。試合を登録すると、<%= Score.human_enum_name(:batting_style, @batting_style) %>の得点内訳における使用率の推移がここに表示されます。
  </p>
  <p class="text-muted small">
    試合を重ねるほど、このグラフにあなたの成長の軌跡が積み上がっていきます。
  </p>
<% else %>
```

- 既存の案内文（登録を促す文）は変更せず、その下に「蓄積予告」の一文を追加する形にする（既存のUX・RSpecの文言アサーションを壊しにくい）。
- クラスは既存の `text-muted` に `small` を added して、補足情報としての視覚的な優先度を下げる（LPの他の補足文言と同じパターン）。



## 変更しないもの

- ルーティング、コントローラー、Aggregatorのロジックは変更しない（表示文言のみ）。
- データが少数件あるときの中間メッセージ（「あと◯件で傾向が見えます」等）は今回のスコープ外。
- 画像・サンプルグラフ等の新規アセットは作らない。



## 進め方

1. 新規ブランチを切る: `fix/growth-dashboard-data-accumulation-teaser`
2. 上記2ファイルを編集し、1コミットにまとめる。
3. `bundle exec rspec && bundle exec rubocop --parallel` を実行し、全てパスすることを確認する。
  - `spec/views/growth_dashboards/index_spec.rb` 等、空状態メッセージの文言をアサーションしているテストがあれば、新しい文言に合わせて更新する（事前に grep で確認する）。
  - `spec/system/homes_spec.rb` 等LPの文言をテストしているケースがあれば同様に確認する。
4. PR作成はユーザーの明示的な指示があってから行う。
5. 本件はplanner/generator/evaluatorを使わない軽量フロー（CLAUDE.mdの「開発ワークフロー」に準拠し、ブランチを切ってから実装する点のみ厳守）。



## 検証方法

- `bundle exec rspec` / `bundle exec rubocop --parallel` が通ること。
- `bin/dev` でローカル起動し、ブラウザで以下を目視確認:
  - LPの「T.T.LOGでできること」に⑤成長ダッシュボードの項目が追加され、他の項目とデザインが揃っていること。
  - 試合データが1件もない（または対象技術のデータがない）テストユーザーでログインし、`/growth_dashboards` の空状態に新しい予告文言が表示されること。
  - 既存のデータがあるユーザーで `/growth_dashboards` を表示し、グラフ表示時に新しい文言が出ないこと（空状態時のみ表示されることの確認）。
